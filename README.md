# MyCalendar

Быстрый оффлайн-календарь, планировщик и учёт времени и финансов («Кэш»). Одна программа без внешних зависимостей с тремя синхронизированными режимами работы:
- **CLI** — классическое интерактивное меню и быстрые команды из терминала;
- **TUI (`mycal -tui`)** — полноэкранный терминальный дашборд с интерактивным календарём, категориями, карточкой записи и статистикой;
- **Web (`mycal web`)** — локальный веб-интерфейс в браузере с живой синхронизацией.

Все данные хранятся локально в обычных JSON-файлах с поддержкой нескольких независимых календарей (`mycal.json`, `mycal--work.json` и т.д.).

## Установка

Готовые сборки — на странице
[**Releases**](https://github.com/khameleonium/MyCal/releases). Скачайте файл для
своей системы, при необходимости дайте право на запуск и запустите из терминала.

| Система | Файл | Запуск |
|---|---|---|
| Windows (64-бит) | `mycal-windows-amd64.exe` | двойной клик или `.\mycal-windows-amd64.exe` |
| Windows (ARM) | `mycal-windows-arm64.exe` | `.\mycal-windows-arm64.exe` |
| Linux (64-бит) | `mycal-linux-amd64` | `chmod +x mycal-linux-amd64 && ./mycal-linux-amd64` |
| Linux (ARM) | `mycal-linux-arm64` | `chmod +x … && ./mycal-linux-arm64` |
| macOS (Intel) | `mycal-darwin-amd64` | `chmod +x … && ./mycal-darwin-amd64` |
| macOS (Apple Silicon) | `mycal-darwin-arm64` | `chmod +x … && ./mycal-darwin-arm64` |

> macOS может заблокировать неподписанный бинарник при первом запуске —
> «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть»,
> либо `xattr -d com.apple.quarantine ./mycal-darwin-arm64`.

Удобно переименовать файл в `mycal` и положить в каталог из `PATH`, тогда команды
из этого README будут работать один в один.

Проверить версию:

```
mycal version
```

## Быстрый старт

```
# 1. Запустите без аргументов — откроется классическое меню CLI
mycal

# 2. Или откройте полноэкранный терминальный дашборд (TUI)
mycal -tui

# 3. Или запустите локальный веб-интерфейс в браузере (по умолчанию порт 8080)
mycal web

# 4. Или добавьте запись одной командой
mycal add
# программа спросит дату, время, название, тип, длительность, кэш, комментарий,
# статус и нужно ли повторять запись

# 5. Посмотрите, что получилось
mycal today          # на сегодня
mycal week           # на текущую неделю
mycal view 2026      # всё за 2026 год
```

Первый запуск ничего не требует настраивать. Файл данных `mycal.json` и файл
настроек `config_mycal.json` создаются автоматически в домашнем каталоге, в `~/.mycal/`
(`%USERPROFILE%\.mycal` в Windows), независимо от того, откуда запущена программа.
Каталог можно переопределить переменной окружения `MYCAL_HOME`.

## Режимы работы: CLI, TUI и Web

### 1. Интерактивный режим (CLI)

Запуск `mycal` без аргументов открывает главное меню:

```
═══ Мои записи ═══ [mycal]
 a | 1. Добавить запись
 v | 2. Посмотреть записи
 d | 3. Удалить запись
 t | 4. Сегодня
 x | 5. Экспорт в CSV
 i | 6. Импорт из CSV / JSON
 s | 7. Настройки
 h | 8. Справка
 q | 9. Выход
 c | 10. Выбрать календарь записей
 n | 11. Создать календарь записей
 u | 12. Отменить последнее действие
```

Вводить можно **и цифру, и букву** (в любой раскладке — см.
[Горячие клавиши](#горячие-клавиши)). В любой момент программу можно закрыть комбинацией **Ctrl+C**.
Почти в каждом диалоге `0` или слово `отмена` возвращает назад, `Enter` означает
«значение по умолчанию» или «пропустить», а при добавлении записи клавиша `8` позволяет
пропустить все оставшиеся необязательные вопросы и сразу сохранить запись.

### 2. Полноэкранный терминальный интерфейс (TUI)

Запуск: `mycal -tui` (или `mycal tui`).

Адаптивный терминальный интерфейс автоматически подстраивается под ширину окна:
- **Широкий (горизонтальный) режим (`ширина ≥ 115`)**: слева отображаются мини-календарь и блок категорий, по центру — таблица записей, справа — карточка выбранной записи и сводка.
  - Переключение фокуса между блоками: `Tab` / `Shift+Tab`, стрелки `←` / `→` или функциональные клавиши:
    - **`F1`** — фокус на блок **«Календарь»**;
    - **`F2`** — фокус на блок **«Категории»**;
    - **`F3`** — фокус на **«Список записей»**;
    - **`F4`** — открыть окно **«Статистика»** (`ModalStats`).
- **Компактный (вертикальный) режим (`ширина < 115`)**: разделы открываются во весь экран с вкладками сверху (`[F1] Записи`, `[F2] Календарь`, `[F3] Карточка`, `[F4] Статистика`).
  - Быстрый переход к нужному разделу: **`F1`–`F4`**;
  - Последовательное перелистывание разделов по кругу: **`[`** и **`]`**;
  - Выбор основного периода вывода записей («Все записи», «Сегодня», «Неделя», «Месяц»): цифры **`1`–`4`**.

Основные клавиши TUI:
- `1`–`4`, `5` (произвольный период), `y` (годовой календарь), `Home` (сегодня) — выбор периода;
- `n` / `+` / `a` — новая запись (поддерживается пакетное создание нескольких записей через `;`), `c` — дублировать выбранную запись;
- `e` — редактировать запись, `f` — быстро изменить одно поле, `v` — мгновенная смена статуса по кругу (`Запланировано → Выполнено → Отменено → ~пусто~`), `s` — окно выбора статуса, `d` — удалить запись;
- `Space` — выделить/снять выделение записи для пакетных операций (`v`, `s`, `f`, `m`, `d`), `A` (`Shift+A`) — выделить все / снять выделение;
- `m` — перенести выбранную запись (или выделенные записи) в другой календарь;
- `u` — отменить последнее действие (`Undo`, до 30 шагов);
- `t` — перейти к списку категорий / переключить фильтр категории;
- `l` — сортировка списка записей (по дате, времени, названию, категории, длительности, кэшу или статусу);
- `/` — живой поиск, `x` — экспорт текущей выборки в CSV, `X` (`Shift+X`) — импорт записей из CSV / JSON с пропуском дубликатов;
- `b` — управление календарями записей (переключение в реальном времени, смена режима хранения `m`, создание нового календаря `+`/`n`);
- `o` — настройки, `?` — полная справка по клавишам, `q` / `Esc` — выход.

### 3. Веб-интерфейс (Web)

Запуск: `mycal web [порт]` (по умолчанию `http://127.0.0.1:8080`) или **`mycal web --lan [порт]`** для доступа с других компьютеров и смартфонов в локальной сети.

- Полноценный локальный дашборд в браузере с мини-календарём, фильтрацией по категориям, поиском, сортировкой по любой колонке и модальными диалогами.
- Поддержка работы по локальной сети (`mycal web --lan` или настройка «Доступ к Web из локальной сети» в `config_mycal.json`): программа сама определяет локальный IP компьютера и выводит готовую ссылку вида `http://192.168.x.x:8080`.
- Селектор календарей в шапке для мгновенного переключения между базами записей в реальном времени и кнопка `+ Календарь` для создания новых календарей.
- Автосохранение выбранного периода в `localStorage` при перезагрузке страницы.
- Возможность работы в фоновом режиме через `mycal service install|start|stop|status`.

## Несколько календарей записей

В каталоге данных (`data_path`) можно вести сколько угодно независимых календарей. Дополнительные календари именуются по шаблону `<имя_базы>--<префикс>.json`:
- **В одном файле (`none`)**: `mycal.json` (основной), `mycal--work.json`, `mycal--sport.json`;
- **По годам (`year`)**: `2026_mycal--work.json`;
- **По месяцам (`month`)**: `2026-11_mycal--work.json`.

Каждый календарь имеет собственную настройку режима хранения (`calendar_splits` в `config_mycal.json`), а активный календарь сохраняется в `active_calendar` и синхронизируется между CLI, TUI и Web. При переименовании базового имени файла (`data_file_name`) автоматически переименовывается вся семья файлов, включая все `--<префикс>` календари.

### Просмотр записей

После выбора периода выводится список с порядковыми номерами, суммарным временем
и разбивкой по типам. Дальше в строке ввода доступно:

| Ввод | Действие |
|---|---|
| `5` | подробности записи №5 |
| `20260615143000` | подробности записи по ID |
| `all` / `все` / `a` | развернуть подробности всех записей списка |
| `\5` или `\20260615143000` | сразу редактировать запись |
| `c5` или `\c5` | дублировать запись №5 (с запросом новой даты и времени) |
| `m5` или `\m5` | перенести запись №5 в другой календарь |
| `u` или `г` | отменить последнее действие (`Undo`) |
| `t` или `т` (также `/t`) | интерактивный фильтр уже выданных записей по типам (с галочками `[✓]` и поиском) |
| `t <текст>` | быстрый фильтр выданных записей по типу (например, `t стрельб`) |
| `/текст` | поиск в текущем списке по названию или типу (например, `/спорт`) |
| `Enter` | назад |

Также в меню **«Посмотреть записи»** и **«Экспорт в CSV»** доступен пункт **`5. По типам`** (`t` / `т`):
позволяет отметить нужные типы флажками (`[✓]`), отфильтровать список типов живым поиском
(например, ввести `стрельб` для мгновенного отображения только подходящих категорий) и выбрать желаемый период.

Повторяющиеся записи в списке помечены звёздочкой `*`.

### Редактирование

Можно изменить любое поле по отдельности или всё сразу («Полностью»). Для
записи из серии повторов программа спросит: **изменить только эту запись** или
**всю серию** (тогда правка применится ко всем её вхождениям).

| Ввод | Действие |
|---|---|
| `Enter` | оставить поле без изменений |
| `-` | очистить комментарий (или сбросить кэш в `0`) |
| `0` | отменить редактирование |

## Команды из терминала (CLI)

Любое действие можно выполнить без входа в меню.

| Команда | Кратко | Что делает |
|---|---|---|
| `mycal -c <префикс> ...` | `--cal` | выполнить любую команду для календаря с указанным префиксом (или `-c main` для основного) без смены активного календаря по умолчанию |
| `mycal add [дата]` | `a` | добавить запись; без даты — спросит всё интерактивно; с датой — только время и остальные поля |
| `mycal view [период] [-t тип]` | `v` | показать записи за период (опционально с фильтром по типу `-t`); без периода — подменю выбора |
| `mycal type [тип]` | — | просмотр записей по типу; без параметров — интерактивный выбор типов |
| `mycal delete <id\|период>` | `d` | удалить запись по ID или все записи за период |
| `mycal export [период] [-t тип]` | `e` | выгрузить записи в CSV рядом с файлом данных (опционально с фильтром `-t`) |
| `mycal import [файл]` | `i` | импортировать записи из CSV или JSON с автоматическим пропуском дубликатов по ID |
| `mycal today` | `t` | записи на сегодня |
| `mycal week` | `w` | записи на текущую неделю (Пн–Вс) |
| `mycal month` | `m` | записи на текущий месяц |
| `mycal -tui` | `tui` | запустить полноэкранный терминальный интерфейс (TUI) |
| `mycal web [--lan] [порт]` | — | запустить веб-интерфейс (по умолчанию порт `8080`; `--lan` открывает доступ по локальной сети) |
| `mycal service <команда>` | — | управление фоновой службой (`install`, `uninstall`, `start`, `stop`, `status`) |
| `mycal help` | `-h`, `--help`, `/?` | справка (работает даже в каталогах с ограничением прав) |
| `mycal version` | `-v`, `--version` | версия |

Примеры:

```bash
mycal add 15.12.2025                  # добавить запись на 15 декабря 2025
mycal -c work add 15.12.2025          # добавить запись сразу в календарь work
mycal -c sport today                  # посмотреть записи на сегодня в календаре sport
mycal view 2026                       # весь 2026 год
mycal view 12.2025                    # декабрь 2025 (также: 2025-12)
mycal view 15-20                      # с 15 по 20 число текущего месяца
mycal view 01.12-15.12                # с 1 по 15 декабря текущего года
mycal view "01.12.2025 – 15.12.2025"  # точный диапазон дат (дефис, тире или пробел)
mycal delete 15-20                    # удалить все записи с 15 по 20 число текущего месяца
mycal delete 20261209110005           # удалить запись по ID
mycal delete 07.2026                  # удалить все записи за июль 2026
mycal export 2026                     # экспорт всего 2026 года в CSV
mycal import backup.csv               # импорт записей из CSV или JSON без дублей
```

CSV сохраняется как `export_ГГГГММДД_ЧЧММСС.csv` в каталоге данных, в кодировке
UTF-8 с BOM — открывается в Excel без «кракозябр».

## Как вводить даты, время и периоды

**Дата** — любой из форматов, разделители `. - / \` или пробел взаимозаменяемы:

| Ввод | Значение |
|---|---|
| `15-06-2026`, `15.06.2026`, `2026-06-15` | 15 июня 2026 |
| `5.1.2026`, `5-1-2026`, `2026-1-5` | 5 января 2026 (однозначные день и месяц) |
| `15-06`, `15.06` | 15 июня текущего (или выбранного в настройках) года |
| `5-1`, `5.1` | 5 января текущего года |
| `32.01.2026` | переносится по календарю → 1 февраля 2026 |

Реакцию на некорректные даты можно настроить: **Настройки → Проверка даты** —
`Выключена` (молча переносить), `Спрашивать`, `Исправлять авто`,
`Переспрашивать`.

**Время** — тоже свободно:

| Ввод | Значение |
|---|---|
| `14:30`, `14.30`, `14-30`, `14 30` | 14:30 |
| `1430` | 14:30 |
| `930` | 09:30 |
| `9` | 09:00 |
| `24` | 00:00 |

**Период** (для `view` / `delete` / `export`):

| Ввод | Диапазон |
|---|---|
| `2026` | весь 2026 год |
| `12` | декабрь текущего года |
| `12.2026`, `2026-12` | декабрь 2026 |
| `10-12` | с октября по декабрь текущего года |
| `15-20` | с 15 по 20 число текущего месяца |
| `01.12-15.12` | с 1 по 15 декабря текущего года |
| `01.12.2025 – 15.12.2025` / `01.12.2025 15.12.2025` | явный диапазон дат (дефис, короткое `–` или длинное `—` тире, пробел) |
| `15.12.2025` | конкретный день |
| пусто | весь текущий год |

## Повторяющиеся записи

При добавлении можно повторять запись **каждый день / неделю / месяц** до
указанной даты (включительно). При запросе частоты поддерживаются как латинские,
так и русские буквы: `d`/`д` (день), `w`/`н` (неделя), `m`/`м` (месяц). Пустой
ввод оставляет запись одиночной.

Каждое повторение сохраняется как отдельная, самостоятельная запись — со своим
ID, но с общей меткой серии (`series_id`).

Это значит:
- любое вхождение можно менять и удалять независимо;
- при правке/удалении программа спрашивает: одно вхождение или вся серия;
- «сломать» серию нельзя — нет «главной» записи, от которой всё зависит.

**Месячный повтор держится своего числа.** Серия с 31 января идёт по датам
28 (или 29) февраля, 31 марта, 30 апреля, 31 мая — в коротких месяцах берётся
последний день, и следующее вхождение возвращается на своё число. Каждая дата
считается от начала серии, поэтому она не «сползает».

Одна серия ограничена 5000 вхождениями; если указанный период даёт больше,
программа предупредит и добавит первые 5000.

## Настройки

**Настройки** (`s` в главном меню CLI, `o` в TUI, иконка шестерёнки в Web):

| Пункт | Описание |
|---|---|
| Режим хранения | один файл / по годам / по месяцам (настраивается индивидуально для каждого календаря). При смене режима файлы **перегруппируются автоматически**, старые удаляются |
| Имя файла данных | базовое имя JSON-файла (без пути и расширения). При смене данные **переносятся** в новые файлы для основного и всех дополнительных `--<префикс>` календарей |
| Продолж. по умолчанию | предлагаемая длительность новой записи, мин |
| Единицы продолжительности | отображение длительности в минутах (`60 мин`) или часах (`1.0 ч`) |
| Тип по умолчанию | предвыбранный тип (категория) при добавлении |
| Путь к данным | каталог с файлами записей (поддерживаются `~`, `$HOME`, `%USERPROFILE%`). Проверяется сразу при вводе |
| Проверка даты | см. [ввод дат](#как-вводить-даты-время-и-периоды) |
| Дата | системное время или зафиксированная вручную (`custom_date`) |
| Период по умолч. в TUI | какой период открывать при старте TUI: `Сегодня`, `Все записи`, `Неделя` или `Месяц` |
| Порт Web-интерфейса | HTTP-порт по умолчанию для `mycal web` (по умолчанию `8080`) |
| Свои списки | категории (типы), свои статусы и частые имена — списки можно просматривать, пополнять и очищать |
| Молча добавлять частые имена | не спрашивать подтверждение в CLI, когда имя стало частым (использовано ≥ 3 раз) |
| Спрашивать при совпадении | предупреждать при совпадении даты и времени записи (по умолчанию выкл — добавляет сразу) |
| Подсказки | поясняющие строки с примерами под каждым пунктом меню CLI (по умолчанию выкл) |

Настройки хранятся в `~/.mycal/config_mycal.json` (`%USERPROFILE%\.mycal\config_mycal.json` в Windows).

## Где хранятся данные

Всё лежит в `~/.mycal/` (или в каталоге из настройки «Путь к данным»).
Настройки и данные старой версии из текущего каталога переносятся при первом запуске:

| Файл | Что это |
|---|---|
| `mycal.json` | записи основного календаря (базовое имя настраивается) |
| `mycal--<префикс>.json` | записи дополнительного календаря (например, `mycal--work.json`) |
| `*.json.bak` | автоматическая резервная копия предыдущей версии файла |
| `config_mycal.json` | настройки (включая `active_calendar` и `calendar_splits`) |
| `2026_mycal.json`, `2026-06_mycal.json` | файлы в режиме хранения «по годам» / «по месяцам» (аналогично для `--<префикс>`) |
| `unknown_mycal.json` | в режимах «по годам» / «по месяцам» — записи, у которых ID не содержит даты и которые нельзя разложить по периодам. Они сохраняются здесь, а не теряются |
| `export_*.csv` | выгрузки в CSV |
| `*.corrupt-<дата>` | повреждённый файл, отложенный при запуске (данные не теряются) |

Запись на диск **атомарная**: сначала во временный файл, синхронизация, затем
замена основного — при сбое питания файл не окажется «наполовину записанным».

### Формат файла данных

Плоский список самодостаточных записей:

```json
{
  "sessions": [
    {
      "id": "20260615143000",
      "time": "14:30",
      "name": "Планёрка",
      "type": "Работа",
      "duration": 45,
      "cash": 1500.5,
      "notes": "еженедельно",
      "status": "Активно",
      "series_id": "20260615143000"
    }
  ]
}
```

- `id` — `ГГГГММДДЧЧММnn`: дата и время записи плюс двузначный счётчик в пределах
  минуты (обеспечивает уникальность). Дата записи берётся отсюда.
- `cash` — финансовая сумма записи (положительная или отрицательная; если `0`, в JSON опускается).
- `series_id` — общий непустой идентификатор для всех записей одной серии
  повторов; у обычных записей поле отсутствует.

Файл можно править вручную — при следующем запуске **Data Doctor** проверит
структуру.

## Что делать, если что-то сломалось

Программа старается сообщать понятным языком:

- **`нет прав доступа` / `недостаточно места на диске`** — при сохранении. Данные
  в памяти не теряются; освободите место / права и повторите действие.
- **`файл mycal.json повреждён…`** — при запуске. Если есть целая резервная копия
  `.bak`, данные восстанавливаются из неё. Если нет — повреждённый файл
  переименовывается в `mycal.json.corrupt-<дата>` (ничего не теряется), а
  календарь открывается пустым.
- **`Data Doctor: обнаружено проблем…`** — при запуске найдены структурные
  дефекты (пустые/битые ID, дубли, отрицательная длительность, нераспознанное
  время). Программа предложит автоматическую починку: непригодные записи
  удаляются, дубликаты ID перегенерируются, время восстанавливается из ID,
  отрицательная длительность обнуляется.
- **`Системные дата/время выглядят неверно`** — если часы компьютера сбиты
  (год < 2000 или > 2100), программа один раз спросит сегодняшнюю дату и
  сохранит её в настройках.

Цветной вывод отключается автоматически при перенаправлении в файл/конвейер и
при установленной переменной `NO_COLOR`.

## Горячие клавиши

Вместо цифр пунктов меню можно нажимать буквы — работают **обе раскладки**
(английская и русская, по позиции клавиши):

- Главное меню CLI (цифры или буквы):
  - `a` / `д` — добавить запись
  - `v` / `п` — просмотр записей
  - `d` / `у` — удалить запись
  - `t` / `с` — записи на сегодня
  - `x` / `э` — экспорт в CSV
  - `i` / `и` — импорт из CSV / JSON
  - `s` / `н` — настройки
  - `h` / `м` — справка
  - `q` / `в` — выход
  - `c` / `к` — выбрать календарь записей
  - `n` / `сз` — создать календарь записей
  - `u` / `о` — отменить последнее действие (`Undo`)
- В подменю буква соответствует латинской подсказке слева от пункта
  (`w`/`m`/`p`/`a` и т.п.). Русская `ф` на месте `a`, `ц` на месте `w` и т.д.
- Русские мнемоники по первой букве пункта имеют приоритет над позиционной раскладкой,
  поэтому `в` — это всегда «Выход», а не «Удалить».
- При выборе повтора записи: `d` / `д` — каждый день, `w` / `н` — каждую неделю, `m` / `м` — каждый месяц.

## Сборка из исходников и разработка

Нужен [Go](https://go.dev/dl/) 1.21 или новее.

```bash
git clone https://github.com/khameleonium/MyCal.git
cd MyCal
go build -o dist/mycal .        # или: go install .
./dist/mycal
```

Проверки (те же, что в CI):

```bash
gofmt -l .          # должно быть пусто
go vet ./...
go test ./...       # модульные + сценарные тесты
```

### Структура

| Пакет | Ответственность |
|---|---|
| `models`   | типы данных (`Session`, `Calendar`, `Config`), единый источник значений по умолчанию |
| `parser`   | разбор и форматирование дат, времени, периодов |
| `storage`  | атомарная загрузка/запись JSON, автообнаружение календарей `--<префикс>`, режимы разбиения файлов, миграция, восстановление из `.bak` |
| `calendar` | единое доменное ядро: реестр полей, CRUD-операции, серии повторов, статистика, экспорт в CSV, переключение календарей и Data Doctor |
| `config`   | схема настроек (`setting_modes`), чтение/запись и автомиграция конфигурации |
| `color`    | ANSI-раскраска с детектом терминала и `NO_COLOR` |
| `app`      | классический интерактивный CLI и консольные подкоманды |
| `tui`      | полноэкранный терминальный интерфейс (TUI) с адаптивной вёрсткой и модальными окнами |
| `web`      | встроенный HTTP-сервер, REST API и локальный веб-дашборд |
| `service`  | управление фоновой системной службой автозапуска |

CI (`.github/workflows/ci.yml`) на каждый push/PR прогоняет `gofmt`, `go vet`,
`staticcheck`, `go test -race` и кросс-сборку под все платформы. Тег `vX.Y.Z`
запускает сборку релизных бинарников (`.github/workflows/release.yml`).
