# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [2.1.0] — 2026-09-18

Аудит кода: исправлены падение, потеря данных и несколько неверно работавших
функций. Формат данных не меняется, обновление безопасно.

### Исправлено — критичное
- **Падение при починке данных.** «Data Doctor» аварийно завершал программу
  (`slice bounds out of range`), если в файле встречались одинаковые ID длиной
  10–11 символов: при перегенерации дубликата ID безусловно обрезался до 12
  символов. Теперь короткий ID дополняется, а не обрезается.
- **Потеря записей при хранении «по годам» / «по месяцам».** Записи, у которых
  ID не содержит даты, молча пропадали при каждом сохранении. Теперь они
  сохраняются в `unknown_<имя>.json` и возвращаются при чтении.
- **Русская `в` в главном меню открывала «Удаление» вместо «Выхода»**, а `м` —
  «Просмотр» вместо «Справки»: мнемоники перекрывались позиционной раскладкой
  (`в` лежит на клавише `d`). Объявленные мнемоники теперь имеют приоритет.

### Исправлено — поведение
- **Месячный повтор больше не «сползает».** Серия с 31 января давала
  3 марта, 3 апреля, 3 мая…; теперь — 28/29 февраля, 31 марта, 30 апреля,
  причём каждая дата считается от начала серии.
- **«Запомнить выбор» в проверке дат действительно запоминается** — режим
  записывался только в память и терялся при выходе.
- **Свой статус, добавленный в список, сохраняется** — раньше он тоже жил
  только до конца сеанса.
- **Комментарий можно очистить** (`-` в поле комментария). Пустой ввод означает
  «без изменений», `0` — отмену, поэтому удалить комментарий было нельзя.
- Просмотр списка больше не работает по устаревшему снимку: после правки или
  удаления запись перечитывается по ID, а удалённая — не показывается.
- Ограничение серии (5000 вхождений) больше не срабатывает молча и не даёт
  лишнюю запись сверх лимита.
- Поиск записи по дате при удалении учитывает дату из настроек, а не системные
  часы (как и просмотр периодов).
- Путь к данным проверяется в момент ввода: неверное значение больше не
  приводит к тому, что программа не запускается в следующий раз.
- Повторяющееся имя не добавляется в список частых имён дважды.

### Добавлено
- **Настройки → Свои списки**: частые имена и свои статусы теперь можно
  просмотреть, пополнить и удалить. Раньше статусы только добавлялись и
  никак не управлялись.
- Регрессионные тесты на все перечисленные дефекты.

### Изменено
- Внутренняя чистка: удалён неиспользуемый код (`models.IDLen`, `Service.Mode`,
  `Service.BaseName`, форматирующие обёртки в `color`), устранено дублирование
  логики поиска и добавления записей, список сортируется один раз на показ.

## [2.0.0] — 2026-09-03

Полный рефакторинг. **Ломает совместимость формата данных** — см. «Миграция».

### Изменено — формат данных
- Файл данных теперь — плоский список `{"sessions": [...]}` без вложенной
  группировки по датам.
- Повторяющиеся записи хранятся как обычные самостоятельные записи с общим
  полем `series_id`. Прежняя схема (запись-шаблон с суффиксом `_r` в поле
  `name`, восстанавливаемая на чтении) удалена.

### Исправлено
- **Проверка даты (режимы «Спрашивать / Исправлять / Переспрашивать») больше не
  является мёртвым кодом.** Раньше разбор опирался на `time.Parse`, который
  отвергает даты вроде `32.01.2026`, поэтому диалог никогда не срабатывал.
  Теперь дата разбирается вручную и переносится по календарю
  (`32.01.2026` → `01.02.2026`).
- Главное меню и запросы больше не уходят в бесконечный цикл на 100% CPU при
  закрытом stdin (EOF).
- Фильтр `/текст` в просмотре теперь фильтрует показанный список, а не всю базу,
  и не переспрашивает период заново.
- Смена режима хранения и **смена имени файла данных** реально переносят файлы
  на диске (раньше прежние файлы оставались, часть данных «терялась из виду»).
  Прежние диалоги «удалить старый файл? (Да/Нет)», ответы на которые
  игнорировались, убраны.
- Правка «всей серии» повтора теперь применяется ко всем вхождениям, включая
  перенос времени.
- Экспорт CSV: UTF-8 BOM для Excel, проверка ошибок записи, файл кладётся рядом
  с данными; при двух выгрузках в одну секунду вторая получает суффикс `_2`.
- Статус `0` в списке статусов означает «пусто», а не «отмена».
- В режиме редактирования «Полностью» тип и статус выбираются из списков, а не
  вводятся текстом (нельзя было сохранить статус как литерал `"3"`).

### Добавлено
- Понятные сообщения о проблемах ФС: «нет прав доступа», «недостаточно места на
  диске», «каталог данных недоступен для записи» (проверяется при старте).
- Повреждённый файл данных/настроек не затирается: восстанавливается из `.bak`
  либо откладывается как `*.corrupt-<дата>`, работа продолжается.
- **Data Doctor** переработан в структурную проверку (пустые/битые ID, дубли,
  отрицательная длительность, нераспознанное время) с безопасной авто-починкой.
- Атомарная запись: временный файл → `fsync` → переименование; `fsync` каталога
  на Unix.
- `mycal version` / `--version`.
- Терпимый разбор времени: `1430`, `930`, `9`, `14.30`, `24` → `00:00`;
  значения вне диапазона отклоняются.
- Обработка SIGINT: отмена незавершённой записи на диск.
- Цвет отключается вне терминала и по `NO_COLOR`.

### Внутреннее
- Пакет `menu` (один файл на 2000 строк) разбит на пакет `app` — по одному
  файлу на экран.
- Гидратация повторов больше не `O(n²)`; вставка записи — без полной
  пересортировки.
- CI: `gofmt`, `go vet`, `staticcheck`, `go test -race`, кросс-сборка;
  отдельный workflow сборки релизов по тегу.
- Модульные и сценарные тесты во всех пакетах (`parser`, `storage`, `calendar`,
  `config`, `app`).

### Миграция с 1.x
Формат `mycal.json` изменился. Автоматического конвертера нет. Варианты:
1. выгрузить записи из 1.x в CSV (`mycal export`), поставить 2.0.0 на чистый
   каталог и внести записи заново, либо
2. сконвертировать `mycal.json` скриптом: из `my_calendar[].session[]` собрать
   плоский массив `sessions[]`, `id` дочерних повторов оставить как есть,
   проставить всем записям серии одинаковый `series_id`.

Старый файл при первом запуске 2.0.0 не читается: он будет отложен как
`mycal.json.corrupt-<дата>` (данные сохранятся, но календарь откроется пустым).
