# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [2.11.0] — 2026-11-07

### Добавлено
- **Управление серией повторов: действие «Эту и все последующие записи серии» (CLI, TUI, Web, Core):**
  - При удалении или редактировании повторяющейся записи добавлен 3-й вариант области применения — «Эту и все последующие записи серии», позволяющий гибко менять расписание с определённой даты без изменения прошлых событий в истории.
  - **Удаление:**
    - **CLI**: меню удаления предлагает 3 варианта: `1. Только эту запись`, `2. Эту и все последующие (N записей)`, `3. Всю серию целиком (N записей)`.
    - **TUI**: диалог подтверждения удаления для повторяющейся серии отображает интерактивный выбор из 3 опций с навигацией стрелками `↑ / ↓`, клавишами `1/2/3` и подтверждением по `Enter`.
    - **Web**: в модальном окне удаления записи появилась опция «Эту и все последующие записи серии» с динамическим подсчётом количества удаляемых записей.
  - **Редактирование:**
    - **CLI**: меню редактирования предлагает 3 варианта области применения изменений (`Только эту`, `Эту и все последующие`, `Всю серию целиком`).
    - **TUI**: в полной форме редактирования записи (`ModalSessionForm`) добавлен пункт «9. Область серии:» (`Только эту запись` / `Эту и последующие` / `Всю серию целиком`) с переключением через `Пробел` или контекстное меню `Enter / →`.
    - **Web**: в окне редактирования записи доступен выбор применения правок: к текущей записи, ко всем последующим или ко всей серии.
  - **Ядро и целостность данных:**
    - Реализованы методы `Service.DeleteSeriesFrom` и `Service.UpdateSeriesFrom`. При частичном редактировании («эту и все последующие») будущие записи автоматически ответвляются в новую подсерию (`SeriesID = fromID`), сохраняя независимость истории прошлых событий от будущих правок.
    - Все операции полностью поддерживают транзакционную многошаговую отмену (`Undo`).

## [2.10.1] — 2026-11-07

### Добавлено
- **Доступ к веб-интерфейсу из локальной сети (LAN — `0.0.0.0`):**
  - Добавлен флаг быстрого запуска `mycal web --lan [порт]` (а также `mycal web 0.0.0.0:8080`, `--host <IP>`, `--no-browser`), при котором веб-сервер слушает все сетевые интерфейсы (`0.0.0.0`) и сразу выводит в консоль готовые ссылки с локальными IP-адресами компьютера (например, `http://192.168.3.129:8080`).
  - Добавлена постоянная настройка `web_lan` («Доступ к Web из локальной сети») во все три интерфейса:
    - **CLI**: `Настройки → a | 19. Доступ к Web из сети (LAN) [Вкл/Выкл]`
    - **TUI**: `Настройки (o) → 14. Доступ к Web из сети` (`Space` или `→`)
    - **Web**: `Настройки (⚙️) → Доступ к Web из локальной сети (LAN)` с живым отображением сетевого адреса `http://<IP>:<порт>`.
  - При включённой настройке `web_lan` фоновая служба (`mycal service`) также автоматически открывает доступ для всех устройств домашней/офисной сети.

## [2.10.0] — 2026-11-07

### Добавлено
- **Статус `~пусто~` (запись без статуса) во всех режимах (CLI, TUI, Web):**
  - В окнах выбора статуса (`ModalStatusPicker` в TUI, меню статуса в CLI, выпадающий список статуса в Web) и при циклическом переключении статуса добавлен явный вариант `~пусто~`, очищающий статус записи (`""`).
- **Мгновенная циклическая смена статуса клавишей `v` / `м` (TUI и Web):**
  - Нажатие `v` / `м` на записи в списке (или на пачке выделенных через `Space` записей) переключает статус по кругу: `Запланировано → Выполнено → Отменено → ~пусто~` одним нажатием без открытия модального окна.
- **Быстрое дублирование записи клавишей `c` / `с` (CLI, TUI, Web):**
  - **TUI**: нажатие `c` / `с` открывает форму создания новой записи, предзаполненную всеми полями текущей записи, с курсором на поле «Дата».
  - **Web**: нажатие `c` / `с` или кнопки «Дубль» в инспекторе открывает модальное окно новой записи с заполненными полями выбранной записи и фокусом на дате.
  - **CLI**: в режиме просмотра списка команда `cN` или `\cN` (например, `c3`) создаёт дубликат записи с запросом новой даты и времени.
- **Перенос записей между календарями клавишей `m` / `ь` (CLI, TUI, Web):**
  - Реализован атомарный перенос одной или нескольких записей между календарями (`Service.MoveSessionsToCalendar`) с автоматическим разрешением коллизий ID в целевом календаре и возможностью создать новый календарь на лету.
  - Доступно по клавише `m` / `ь` в TUI (для текущей записи или пачки выделенных `Space`), в Web (по клавише `m` / `ь` или кнопке «В календарь») и в CLI при просмотре записей (`mN` / `\mN`).
- **Многошаговая отмена действий (`Undo`) по `u` / `г` / `Ctrl+Z` (CLI, TUI, Web):**
  - В ядре `calendar.Service` реализован транзакционный стек снимков состояния (до 30 шагов) с поддержкой группировки пакетных операций (`BeginUndoTx` / `EndUndoTx`).
  - Нажатие `u` / `г` в TUI, `u` / `г` / `Ctrl+Z` (или кнопки `↶ Отмена`) в Web, а также пункт `u | 12. Отменить последнее действие` и команда `u` при просмотре в CLI мгновенно откатывают последнее добавление, правку, смену статуса, удаление или импорт.
- **Быстрый выбор календаря из командной строки (`-c <префикс>`):**
  - Глобальный флаг `-c <префикс>` / `--cal <префикс>` (и `-c main` для основного календаря) позволяет выполнять любую команду (`mycal -c work add`, `mycal -c sport today`, `mycal -c work -tui`, `mycal -c work web`) для нужного календаря без перезаписи активного календаря по умолчанию в `config_mycal.json`.
- **Импорт записей из CSV и JSON с дедупликацией (`Service.ImportFile`):**
  - Поддержка импорта как из стандартного CSV-формата MyCal (`ID;Дата;Время;Название;Категория;Длительность (мин);Кэш;Статус;Комментарий`), так и из произвольных CSV-таблиц без колонки ID (с автогенерацией ID по дате и времени) и JSON-файлов (`{"sessions":[...]}` или `[...]`).
  - Записи с уже существующими в базе ID автоматически пропускаются без создания дублей; новые категории и статусы из файла автоматически регистрируются в настройках.
  - Доступно через `mycal import <файл>`, пункт `i | 6. Импорт из CSV / JSON` в CLI, клавишу `X` / `Ч` (`Shift+X`) в TUI и кнопку «Импорт» (`X`) в Web.

### Оптимизировано и исправлено
- **Кратный рост скорости и снижение аллокаций памяти на больших базах (5 000+ записей):**
  - Добавлен zero-allocation метод `Session.DateKey()`, используемый при сортировке (`storage.SortSessions`, `calendar.CompareSessions`) и фильтрации диапазонов (`calendar.InRange`, `tui.reloadSessions`, `tui.renderCalendarBox`), что сократило число аллокаций при перезагрузке списка в TUI более чем в 300 раз.
  - В `calendar.GenerateID` исключено полное копирование карты всех ID на каждый вызов (проверяются только записи с совпадающим 12-символьным префиксом даты-времени), а в `calendar.AddBatch` добавлена пакетная индексация `O(N + M)` вместо `O(N * M)`.
  - В `calendar.Update` и `calendar.UpdateSeries` пересортировка массива выполняется только при изменении времени записи.
  - Пакетное изменение поля (`f`) и пакетное удаление (`d`) для выделенных через `Space` записей в TUI переведены на единую транзакцию `Undo` и однократное сохранение на диск (ускорение пакетной правки 20 записей на базе из 5 000 записей с `1.65 с` до `73 мс`).
  - В TUI внедрено кэширование расчёта статистики (`cachedStats`) между кадрами и переиспользование экранного буфера (`screenBuf`) без повторных аллокаций при навигации.

## [2.9.0] — 2026-11-07

### Добавлено
- **Поддержка нескольких календарей записей (`обычное_имя_файла--префикс.json`):**
  - В каталоге записей (`data_path`) программа автоматически обнаруживает все файлы календарей с суффиксом `--<префикс>.json` перед расширением:
    - в одном файле (`none`): `<имя_базы>--<префикс>.json` (например, `mycal--work.json`);
    - по годам (`year`): `<ГГГГ>_<имя_базы>--<префикс>.json` (например, `2026_mycal--work.json`);
    - по месяцам (`month`): `<ГГГГ-ММ>_<имя_базы>--<префикс>.json`.
  - Каждый календарь имеет собственную индивидуальную настройку режима хранения (`calendar_splits` в `config_mycal.json`: единый файл, по годам или по месяцам), а текущий выбранный календарь сохраняется в `active_calendar`.
  - В едином ядре (`storage.DiscoverCalendars`, `Service.ListCalendars`, `Service.SwitchCalendar`, `Service.CreateCalendar`) реализовано автообнаружение, создание и переключение календарей.
  - **CLI**: в главном меню и меню настроек добавлены пункты «Выбрать календарь записей» (`c | 9`) и «Создать календарь записей» (`n | 10`) с интерактивными диалогами выбора префикса и режима хранения (единый или погодовой файл).
  - **TUI**: добавлено окно управления календарями по клавише `[b]` (`ModalCalendarManager`) с переключением календарей **в реальном времени** при выборе из списка (`↑`/`↓` или `1–9`), переключением режима хранения клавишей `[m]` и созданием нового календаря клавишей `[+ / n]`.
  - **Web**: в верхней панели добавлен селектор календарей с переключением **в реальном времени** и кнопка `+ Календарь` (диалог создания нового календаря с выбором режима хранения и живым предпросмотром имени файла), а также REST API `/api/calendars`.
- **Навигация функциональными клавишами `F1`–`F4` в TUI:**
  - **Компактный (вертикальный) режим (`width < 115`)**: клавиши `1`–`4` выбирают период вывода записей («Все записи», «Сегодня», «Неделя», «Месяц»), клавиши `[` и `]` листают вкладки разделов по кругу, а функциональные клавиши `F1`–`F4` мгновенно переключают разделы (`[F1] Записи`, `[F2] Календарь`, `[F3] Карточка`, `[F4] Статистика`).
  - **Широкий (горизонтальный) режим (`width >= 115`)**: функциональные клавиши дополняют навигацию по `Tab` и стрелкам — `F1` устанавливает фокус на блок «Календарь», `F2` — на блок «Категории», `F3` — на «Список записей», а `F4` открывает окно детальной статистики (`ModalStats`).

### Изменено и удалено
- **Удалён показатель «Средний кэш» (`AvgCash`):** из статистики CLI, доменного ядра (`calendar.StatsSummary`) и Web-интерфейса убран неиспользуемый показатель среднего кэша (оставлен суммарный кэш и разбивка по категориям).

### Исправлено (аудит кода и кроссплатформенность Linux / Windows)
- **Единообразная и безопасная работа с путями (`DataPath`) на Linux и Windows:**
  - В `storage.ExpandPath` добавлена поддержка раскрытия переменных окружения Windows `%VAR%` (например, `%USERPROFILE%\myCal`, `%APPDATA%\myCal`) и путей `~\...` наряду с `$VAR` и `~/...`.
  - Введены функции `config.EffectiveDataDir` и `config.DataPathDisplay`: пустой `DataPath` в конфиге всегда резолвится в глобальный каталог (`~/.mycal` на Linux/macOS, `%USERPROFILE%\.mycal` на Windows) и больше не перезаписывается строкой `"~/.mycal"` при открытии настроек TUI или запуске из разных рабочих папок.
  - В `main.go` исправлено определение рабочего каталога на Windows при запуске через Планировщик задач (`C:\Windows\System32`).
  - Редактирование пути `DataPath` в настройках TUI по `Backspace` переведено на посимвольную (`[]rune`) обрезку для корректной работы с кириллическими путями.
- **Защита данных при смене режима хранения и переименовании базы:**
  - Исправлен порядок операций при смене `split_mode` в `ModalCalendarManager` (`[m]`) и `POST /api/calendars`: переключение активного календаря (`SwitchCalendar`) теперь гарантированно выполняется до конвертации режима хранения (`SetMode` + `Save`), исключая перезапись целевого календаря записями предыдущего.
  - Добавлена функция `storage.RenameFamilyDataFiles`: при смене базового имени файла (`data_file_name`) в настройках CLI, TUI и Web автоматически переименовываются как основной календарь, так и все дополнительные календари `--<префикс>` во всех режимах разбиения (`none`, `year`, `month`).
- **Валидация, потокобезопасность и оптимизация:**
  - В `Server.updateField` (Web API) добавлена строгая валидация времени (`parser.ParseTime`) и положительной длительности, а также авторегистрация новых категорий и статусов.
  - В модальных диалогах TUI (`ModalSessionForm`, `ModalQuickEditField`, `ModalStatusPicker`, `ModalConfirmDelete`) добавлена проверка ошибок сохранения на диск с выводом сообщения пользователю.
  - Устранена гонка данных (`data race`) при ресайзе терминала (`SIGWINCH` в `tui/app.go`), все методы чтения/записи `calendar.Service` защищены `sync.RWMutex`.
  - Исключена лишняя перекомпиляция регулярных выражений при отрисовке кадров TUI, частота опроса `os.Stat` снижена с 4 раз/сек до 1 раза/сек, а пакетное создание записей через `;` в Web объединено в один запрос.

## [2.8.0] — 2026-11-07

### Изменено и унифицировано
- **Единое модульное ядро (`calendar/fields.go`, `calendar/operations.go`, `config/schema.go`) и тонкие UI-адаптеры (`CLI`, `TUI`, `Web`):**
  - Создан единый реестр полей записи `calendar.SessionFields` (с метаданными, парсингом, валидацией и форматированием) и общие функции `ParseCash`, `FormatCash`, `SplitEntryNames`, `CheckDateInput`.
  - Внедрены единые движки создания и обновления записей `Service.CreateEntries` и `Service.UpdateEntry` (включая разбиение нескольких названий через `;`/перенос строки, генерацию серий повторов, перенос даты с пересборкой ID и автопополнение пользовательских списков категорий/статусов/имён).
  - Унифицирован расчёт статистики (`calendar.ComputeStats`) и экспорт в CSV (`Service.ExportCSV`) для всех трёх режимов.
  - В CLI-редактировании добавлен пункт `9. Дата` (перенос записи на другую дату, как в TUI и Web), а в TUI при сохранении формы учитывается настройка `date_check_mode`.
- **Привязка настроек к интерфейсам (`setting_modes`):**
  - В `config_mycal.json` и `config/schema.go` для каждой настройки заданы теги режимов (`setting_modes`), определяющие, в каких интерфейсах настройка отображается:
    - `date_check_mode`: `["cli", "tui"]`
    - `use_system_date`, `custom_date`, `web_port` и основные параметры: `["cli", "tui", "web"]` (в TUI и Web добавлен полноценный ввод фиксированной даты `custom_date`, в CLI — настройка `web_port`)
    - `tui_default_period`: `["tui"]`
    - `show_hints`, `silent_add_names`: `["cli"]`
- **Автоматическая миграция файла настроек при загрузке (`config.Load`):**
  - При обнаружении старого или неполного файла настроек программа считывает и сохраняет все знакомые поля, удаляет старый файл и создаёт новый актуальный файл со всеми сохранёнными пользовательскими значениями и новыми полями.

## [2.2.0] — 2026-10-03

Полный аудит кода и устранение функциональных ошибок: расширение возможностей
парсера периодов и дат, защита от потери данных при шардировании, поддержка
русских горячих клавиш при повторах и независимость встроенной справки от прав на запись.

### Исправлено — критичное
- **Неверное удаление и просмотр при диапазоне дней.** Ввод диапазона дней текущего месяца
  (например, `15-20` или `10-15`) в командах `mycal view` и `mycal delete` ошибочно

- **Ошибочный отказ при валидации корректных дат.** Функция `ParseDateStrict`
  принимала только двухзначные форматы дня и месяца (`02-01-2006`). Даты с однозначными

  блокируя пользователя при настройке `Проверка даты: Переспрашивать`. Теперь однозначные
  форматы полностью поддержаны.
- **Сбой шаблонов `filepath.Glob` в режимах разбиения.** Использование квадратных скобок `[` и `]`
  в имени файла базы ломало поиск существующих файлов при хранении «по годам» и «по месяцам»,
  что могло приводить к недоступности сохранённых записей. Квадратные скобки теперь запрещены
  в `sanitizeBaseName`.

### Добавлено и улучшено
- **Новые форматы периодов:**
  - Поддержка формата `YYYY-MM` (например, `2025-12` или `2026-05`).
  - Поддержка короткого тире (`–`, en-dash) и длинного тире (`—`) в диапазонах дат (например, `01.12.2025 – 15.12.2025`).
- **Справка доступна всегда.** Вызов `mycal help`, `-h`, `--help`, `/?` теперь перехватывается
  до инициализации каталога данных (`EnsureWritableDir`), благодаря чему справка работает даже
  в каталогах только для чтения или без прав на запись.
- **Русская раскладка для режима повтора.** При выборе частоты повтора записи теперь принимаются
  русские буквы `д` (день), `н` (неделя), `м` (месяц) наряду с английскими `d`, `w`, `m`.
- **Защита от смещения дат из-за часовых поясов.** Вычисление последнего дня месяца переведено
  в `time.UTC` во избежание сдвигов при переходе на летнее/зимнее время.
- **Строгая проверка месяцев в неполных датах.** Даты из двух чисел (`DD-MM`) с месяцем больше 12
  теперь отклоняются с ошибкой и больше не сдвигаются в будущие годы.

  «без изменений», `0` — отмену, поэтому удалить комментарий было нельзя.
- Просмотр списка больше не работает по устаревшему снимку: после правки или
  удаления запись перечитывается по ID, а удалённая — не показывается.
- Ограничение серии (5000 вхождений) больше не срабатывает молча и не даёт
  лишнюю запись сверх лимита.
- Поиск записи по дате при удалении учитывает дату из настроек, а не системные
  часы (как и просмотр периодов).
- Путь к данным проверяется в момент ввода: неверное значение больше не
  приводит к тому, что программа не запускается в следующий раз.
- Повторяющееся имя не добавляется в список частых имён дважды.

### Добавлено
- **Настройки → Свои списки**: частые имена и свои статусы теперь можно
  просмотреть, пополнить и удалить. Раньше статусы только добавлялись и
  никак не управлялись.
- Регрессионные тесты на все перечисленные дефекты.

### Изменено
- Внутренняя чистка: удалён неиспользуемый код (`models.IDLen`, `Service.Mode`,
  `Service.BaseName`, форматирующие обёртки в `color`), устранено дублирование
  логики поиска и добавления записей, список сортируется один раз на показ.

## [2.0.0] — 2026-09-03

Полный рефакторинг. **Ломает совместимость формата данных** — см. «Миграция».

### Изменено — формат данных
- Файл данных теперь — плоский список `{"sessions": [...]}` без вложенной
  группировки по датам.
- Повторяющиеся записи хранятся как обычные самостоятельные записи с общим
  полем `series_id`. Прежняя схема (запись-шаблон с суффиксом `_r` в поле
  `name`, восстанавливаемая на чтении) удалена.

### Исправлено
- **Проверка даты (режимы «Спрашивать / Исправлять / Переспрашивать») больше не
  является мёртвым кодом.** Раньше разбор опирался на `time.Parse`, который
  отвергает даты вроде `32.01.2026`, поэтому диалог никогда не срабатывал.
  Теперь дата разбирается вручную и переносится по календарю
  (`32.01.2026` → `01.02.2026`).
- Главное меню и запросы больше не уходят в бесконечный цикл на 100% CPU при
  закрытом stdin (EOF).
- Фильтр `/текст` в просмотре теперь фильтрует показанный список, а не всю базу,
  и не переспрашивает период заново.
- Смена режима хранения и **смена имени файла данных** реально переносят файлы
  на диске (раньше прежние файлы оставались, часть данных «терялась из виду»).
  Прежние диалоги «удалить старый файл? (Да/Нет)», ответы на которые
  игнорировались, убраны.
- Правка «всей серии» повтора теперь применяется ко всем вхождениям, включая
  перенос времени.
- Экспорт CSV: UTF-8 BOM для Excel, проверка ошибок записи, файл кладётся рядом
  с данными; при двух выгрузках в одну секунду вторая получает суффикс `_2`.
- Статус `0` в списке статусов означает «пусто», а не «отмена».
- В режиме редактирования «Полностью» тип и статус выбираются из списков, а не
  вводятся текстом (нельзя было сохранить статус как литерал `"3"`).

### Добавлено
- Понятные сообщения о проблемах ФС: «нет прав доступа», «недостаточно места на
  диске», «каталог данных недоступен для записи» (проверяется при старте).
- Повреждённый файл данных/настроек не затирается: восстанавливается из `.bak`
  либо откладывается как `*.corrupt-<дата>`, работа продолжается.
- **Data Doctor** переработан в структурную проверку (пустые/битые ID, дубли,
  отрицательная длительность, нераспознанное время) с безопасной авто-починкой.
- Атомарная запись: временный файл → `fsync` → переименование; `fsync` каталога
  на Unix.
- `mycal version` / `--version`.
- Терпимый разбор времени: `1430`, `930`, `9`, `14.30`, `24` → `00:00`;
  значения вне диапазона отклоняются.
- Обработка SIGINT: отмена незавершённой записи на диск.
- Цвет отключается вне терминала и по `NO_COLOR`.

### Внутреннее
- Пакет `menu` (один файл на 2000 строк) разбит на пакет `app` — по одному
  файлу на экран.
- Гидратация повторов больше не `O(n²)`; вставка записи — без полной
  пересортировки.
- CI: `gofmt`, `go vet`, `staticcheck`, `go test -race`, кросс-сборка;
  отдельный workflow сборки релизов по тегу.
- Модульные и сценарные тесты во всех пакетах (`parser`, `storage`, `calendar`,
  `config`, `app`).

### Миграция с 1.x
Формат `mycal.json` изменился. Автоматического конвертера нет. Варианты:
1. выгрузить записи из 1.x в CSV (`mycal export`), поставить 2.0.0 на чистый
   каталог и внести записи заново, либо
2. сконвертировать `mycal.json` скриптом: из `my_calendar[].session[]` собрать
   плоский массив `sessions[]`, `id` дочерних повторов оставить как есть,
   проставить всем записям серии одинаковый `series_id`.

Старый файл при первом запуске 2.0.0 не читается: он будет отложен как
`mycal.json.corrupt-<дата>` (данные сохранятся, но календарь откроется пустым).
